# NailGlow Booking – คู่มือติดตั้งและรันโปรเจกต์

โปรเจกต์นี้คือหน้าแรกของเว็บไซต์ NailGlow ที่มี: Hero, **AI วิเคราะห์สีผิว**,
**AI แนะนำลายเล็บ**, **Virtual Nail Try-On**, **AI วิเคราะห์ลายจากรูปอ้างอิง +
ประเมินเวลาทำ**, บริการของร้าน, ลายเล็บยอดนิยม, โปรโมชั่น, รีวิวลูกค้า และ
**ระบบจองคิวแบบขั้นตอน (wizard)** ที่มีปฏิทินเลือกวัน, เลือกเวลาว่าง,
เลือกบริการแยกหมวดหมู่ (ทำผม / ทำเล็บ), และแนบรูปภาพอ้างอิงตามเงื่อนไข

สร้างด้วย **React + Vite + Tailwind CSS** — ฟีเจอร์ AI ทั้งหมดยังไม่เชื่อมฐานข้อมูล/บริการ AI
จริง แต่ใช้ตรรกะที่รันบนเบราว์เซอร์ล้วนๆ (ดูรายละเอียดด้านล่าง) เพื่อให้ทดลองใช้งานได้ทันที
และเปลี่ยนไปต่อ API จริงภายหลังได้ง่าย

## AI วิเคราะห์สีผิว (Skin Tone Analysis)

ทำงานทั้งหมดบนเบราว์เซอร์ ไม่มีการส่งรูปไปที่ไหน:

1. ผู้ใช้อัปโหลดรูปมือ
2. กด "วิเคราะห์สีผิว" → ระบบวาดรูปลงบน `<canvas>` ที่ซ่อนไว้ แล้วอ่านค่าสีเฉลี่ย
   (R, G, B) จากพิกเซลทั้งหมด
3. ใช้สูตร `warmth = (R - B) / 255` จัดกลุ่มเป็น **Warm / Cool / Neutral Tone**
   (นี่คือ heuristic ง่ายๆ ไม่ใช่โมเดล AI จริง — เหมาะสำหรับ demo แต่ควรเปลี่ยนไปใช้
   โมเดล ML หรือ API วิเคราะห์ภาพจริงก่อนขึ้นโปรดักชัน)
4. แสดงโทนสีที่แนะนำพร้อมคำแนะนำ

ผลลัพธ์ (`warm` / `cool` / `neutral`) จะถูกส่งขึ้นไปเก็บที่ `App.jsx` ผ่าน prop
`onAnalyzed` เพื่อให้ส่วน "AI แนะนำลายเล็บ" นำไปใช้คำนวณต่อ

## AI แนะนำลายเล็บ (Nail Recommendation)

- ข้อมูลลายเล็บทั้งหมดอยู่ใน `src/data/nailCatalog.js` แต่ละลายมีคะแนนความเข้ากันกับ
  แต่ละโทนผิว (`toneFit`) และคะแนนความนิยมพื้นฐาน (`popularity`)
- ฟังก์ชัน `scoreDesignForTone()` คำนวณ % ความเหมาะสม = คะแนนตามโทนผิว 75% +
  คะแนนความนิยม 25% แล้ว `getRankedDesigns()` จะเรียงจากมากไปน้อยและตัด Top 5
- ถ้ายังไม่เคยวิเคราะห์สีผิว จะโชว์เป็น "ลายเล็บยอดนิยม" ทั่วไป (เรียงตามความนิยม)
  พร้อมปุ่มชวนไปวิเคราะห์สีผิวก่อน
- ถ้าวิเคราะห์สีผิวแล้ว จะโชว์เป็นลายที่ "เหมาะกับคุณ" พร้อม badge % และ progress bar
  ของแต่ละลาย บอกราคาและเวลาที่ใช้ทำด้วย

## Virtual Nail Try-On

- SVG มือวาดขึ้นเองด้วย React (ไม่ใช่รูปถ่ายจริง) อยู่ใน `VirtualTryOn.jsx`
- เลือกสี (10 สี) และลวดลาย (สีเรียบ / French Tip / กากเพชร) แล้วเล็บบน SVG จะเปลี่ยนสีทันที
- เทียบ "ก่อน" (เล็บธรรมชาติ) กับ "หลัง" (สีที่เลือก) แบบเห็นพร้อมกันสองมือ
- กด "บันทึกลายที่เลือก" เพื่อเก็บชุดสี+ลายไว้ดูภายหลัง (เก็บใน state ของหน้าเว็บ
  เท่านั้น หายเมื่อรีเฟรชหน้า — ยังไม่บันทึกลง backend)

## AI วิเคราะห์ลายเล็บจากรูปอ้างอิง + AI ประเมินเวลาการทำ

ใช้ตรรกะร่วมกับ AI วิเคราะห์สีผิว โดยรวมฟังก์ชันวิเคราะห์ภาพไว้ที่
`src/utils/imageAnalysis.js` ที่เดียว:

- `analyzeReferenceStyle()` วาดรูปลง canvas แล้ววัด **ความอิ่มตัวของสีเฉลี่ย**
  และ **ความหลากหลายของสีในภาพ (variance)** จากนั้นจัดกลุ่มเป็นสไตล์
  **Minimal / Classic / Bold-Colorful** — เป็น heuristic ง่ายๆ เช่นเดียวกับการวิเคราะห์
  สีผิว ไม่ใช่การรู้จำลวดลายจริง
- ทุกลายใน `nailCatalog.js` มี `styleTag` กำกับไว้ ฟังก์ชัน `getDesignsByStyle()`
  จะดึงลายในร้านที่ตรงกับสไตล์ที่วิเคราะห์ได้มาแสดงเป็น "ลายที่ใกล้เคียงภายในร้าน"
- ฟีเจอร์นี้มี 2 จุดที่ใช้งานได้:
  1. **หน้าแรก** (`ReferenceImageAnalysis.jsx`, section `#ai-reference`) — อัปโหลดรูป
     ที่เซฟจาก Pinterest/IG มาดูสไตล์และลายใกล้เคียงแบบสำรวจทั่วไป
  2. **ระหว่างจองคิว** (ในขั้น "รายละเอียดเพิ่มเติม" ของหมวดทำเล็บ, ไฟล์
     `booking/ServiceDetails.jsx`) — ใช้รูปที่แนบตอนจองมาวิเคราะห์ได้เลย ผลลัพธ์จะ
     คำนวณ **เวลาทำเพิ่มเติม** ตามสไตล์ (`STYLE_EXTRA_MINUTES`) แล้วส่งขึ้นไปรวมกับ
     เวลาบริการพื้นฐานใน `BookingWizard.jsx` (ตัวแปร `estimatedDuration`) และแสดงใน
     สรุปการจองที่ขั้นตอนสุดท้าย

## ขั้นตอนการจองคิว (Booking Flow)

1. **เลือกบริการ** — เลือกหมวดหมู่ก่อน (ทำผม / ทำเล็บ) แล้วเลือกบริการย่อยในหมวดนั้น
   แยกกันชัดเจน ลูกค้าจะไม่เห็นบริการของอีกหมวดปนกัน
2. **รายละเอียดเพิ่มเติม** (แสดงเฉพาะบางกรณี)
   - ถ้าเลือก **ทำผม** และบริการนั้นเป็น "ทำสีผม" → ระบบจะให้เลือกโทนสี +
     แนบรูปตัวอย่างสีที่ต้องการ
   - ถ้าเลือก **ทำผม** บริการอื่นที่ไม่ใช่ทำสี (ตัดผม, สระไดร์ ฯลฯ) →
     ข้ามขั้นตอนนี้ไปเลือกวันเวลาได้ทันที
   - ถ้าเลือก **ทำเล็บ** (ทุกบริการ) → ให้แนบรูปลายเล็บที่อยากได้ พร้อมปุ่มให้ AI
     วิเคราะห์ลายและประเมินเวลาทำเพิ่มเติมได้ทันที (ไม่บังคับกด)
3. **เลือกวันและเวลา** — ปฏิทินให้เลือกวันที่ (วันที่ผ่านมาแล้วและวันหยุดร้านจะกดไม่ได้)
   จากนั้นแสดงช่วงเวลาว่างของวันนั้น (ช่วงที่ถูกจองแล้วจะกดไม่ได้)
4. **ข้อมูลติดต่อ** — กรอกชื่อ, เบอร์โทร, ไอดีไลน์ พร้อมสรุปรายการจองก่อนกดยืนยัน

ตรรกะทั้งหมดของขั้นตอนนี้ควบคุมโดย `BookingWizard.jsx` ซึ่งจะคำนวณอัตโนมัติว่า
ต้องแสดงขั้นตอน "รายละเอียดเพิ่มเติม" หรือไม่ ตามหมวดหมู่/บริการที่เลือก

## ขั้นตอนที่ 1: ติดตั้งเครื่องมือพื้นฐาน

ต้องมี **Node.js** (แนะนำเวอร์ชัน 18 ขึ้นไป) ติดตั้งในเครื่องก่อน
เช็คได้ด้วยคำสั่ง:

```bash
node -v
npm -v
```

ถ้ายังไม่มี ให้โหลดจาก https://nodejs.org (เลือกเวอร์ชัน LTS)

## ขั้นตอนที่ 2: สร้างโปรเจกต์ React ด้วย Vite (ถ้าเริ่มจากศูนย์)

ปกติแล้วถ้าจะสร้างโปรเจกต์ React ใหม่ตั้งแต่ต้น จะใช้คำสั่ง:

```bash
npm create vite@latest nailglow-booking -- --template react
cd nailglow-booking
npm install
```

คำสั่งนี้จะสร้างโครงสร้างโปรเจกต์ React พื้นฐานให้อัตโนมัติ
(ในกรณีนี้ผมสร้างไฟล์ทั้งหมดให้แล้ว คุณสามารถ **แตกไฟล์ zip ที่แนบมาแทนขั้นตอนนี้ได้เลย**)

## ขั้นตอนที่ 3: ติดตั้ง Tailwind CSS

ในโปรเจกต์ที่แตกไฟล์มา ไฟล์ config ของ Tailwind (`tailwind.config.js`,
`postcss.config.js`) ถูกสร้างไว้ให้แล้ว แต่ถ้าอยากรู้ขั้นตอนติดตั้งเองตั้งแต่ต้น
จะใช้คำสั่ง:

```bash
npm install -D tailwindcss postcss autoprefixer
npx tailwindcss init -p
```

จากนั้นตั้งค่า `content` ใน `tailwind.config.js` ให้ชี้ไปที่ไฟล์ `.jsx` ทั้งหมด
และเพิ่ม `@tailwind base; @tailwind components; @tailwind utilities;`
ในไฟล์ `src/index.css` (ทำไว้ให้แล้วในโปรเจกต์นี้)

## ขั้นตอนที่ 4: ติดตั้ง dependencies ของโปรเจกต์นี้

1. แตกไฟล์ `nailglow-booking.zip` ที่ได้รับ
2. เปิด Terminal / Command Prompt แล้ว `cd` เข้าไปในโฟลเดอร์โปรเจกต์
3. รันคำสั่ง:

```bash
npm install
```

คำสั่งนี้จะติดตั้ง React, Vite, Tailwind ตามที่ระบุใน `package.json`

## ขั้นตอนที่ 5: รันโปรเจกต์ในโหมดพัฒนา (Dev Server)

```bash
npm run dev
```

Vite จะแสดง URL เช่น `http://localhost:5173` ให้เปิดในเบราว์เซอร์
เพื่อดูเว็บไซต์ที่รันอยู่จริง แก้โค้ดตรงไหนหน้าเว็บจะอัปเดตให้อัตโนมัติ (Hot Reload)

## ขั้นตอนที่ 6: ทำความเข้าใจการทำงานของแต่ละไฟล์

- **`src/main.jsx`** – จุดที่ React เริ่ม render แอปเข้าไปใน `<div id="root">`
  ของ `index.html`
- **`src/App.jsx`** – นำ component ของแต่ละ section (Header, Hero, Services ฯลฯ)
  มาเรียงต่อกันเป็นหน้าเว็บเดียว
- **`src/data/bookingData.js`** – รวมข้อมูลบริการทั้งหมดแยกตามหมวดหมู่ (`servicesByCategory`),
  โทนสีผมให้เลือก (`colorShades`), ช่วงเวลาทำการ (`timeSlots`) และฟังก์ชันจำลองคิวที่ถูกจองแล้ว
  (`getBookedSlots`) — ถ้าจะเชื่อมกับฐานข้อมูลจริงในอนาคต จุดนี้คือจุดที่ต้องเปลี่ยนไปดึงจาก API แทน
- **`src/components/booking/BookingWizard.jsx`** – "สมอง" ของระบบจองคิวทั้งหมด
  เก็บ state ของทุกขั้นตอน (บริการ, โทนสี, รูปภาพ, ผลวิเคราะห์เวลาทำ, วันเวลา,
  ข้อมูลติดต่อ) และคำนวณว่าควรมีกี่ขั้นตอนตามเงื่อนไข (ทำสีผม/ทำเล็บ ต้องมีขั้น
  "รายละเอียดเพิ่มเติม" ส่วนบริการผมอื่นๆ ข้ามได้) รวมถึงคำนวณ `estimatedDuration`
  รวมจากบริการพื้นฐาน + เวลาเพิ่มจาก AI วิเคราะห์ลาย (ถ้ามี)
- **`src/components/booking/ServiceDetails.jsx`** – นอกจากเลือกโทนสี/แนบรูปแล้ว
  ในหมวดทำเล็บยังมีปุ่มให้ AI วิเคราะห์รูปที่แนบและประเมินเวลาทำได้ทันทีในหน้านี้
- **`src/utils/imageAnalysis.js`** – รวมฟังก์ชันวิเคราะห์รูปด้วย `<canvas>` ไว้ที่เดียว
  ใช้ทั้งใน `SkinToneAnalysis.jsx`, `ReferenceImageAnalysis.jsx` และ
  `booking/ServiceDetails.jsx` เพื่อไม่ให้ตรรกะซ้ำกันหลายที่
- **`src/components/booking/DateTimePicker.jsx`** – ปฏิทินเขียนขึ้นเองด้วย JavaScript ล้วน
  (ไม่ใช้ library ปฏิทินภายนอก) คำนวณจำนวนวันในเดือน, ปิดวันที่ผ่านมาแล้วและวันหยุดร้าน,
  และแสดงช่วงเวลาว่าง/ไม่ว่างของวันที่เลือก
- **`tailwind.config.js`** – กำหนดโทนสี (สีชมพู/โรส/พีช) และฟอนต์ที่ใช้ทั่วเว็บไซต์

## ขั้นตอนที่ 7: ต่อยอดในอนาคต (ยังไม่ต้องทำตอนนี้)

เมื่อพร้อมทำระบบหลังบ้านจริง สิ่งที่ต้องเพิ่มคือ:

1. **Backend API** (เช่น Node.js/Express หรือ Firebase) รับข้อมูลจากฟอร์ม
   และบันทึกลงฐานข้อมูล
2. เปลี่ยนส่วน `TODO` ใน `BookingForm.jsx` ให้ยิง `fetch()` ไปที่ API จริง
   แทนการเก็บไว้ใน state เฉยๆ
3. เพิ่มระบบอัปโหลดรูปภาพขึ้น cloud storage (เช่น Firebase Storage, Cloudinary)
4. เปลี่ยน heuristic วิเคราะห์ภาพใน `src/utils/imageAnalysis.js` (สูตรสี/ความอิ่มตัวแบบง่าย)
   ให้เป็นโมเดล AI / API วิเคราะห์ภาพจริง เพื่อความแม่นยำระดับโปรดักชัน
5. เชื่อม `nailCatalog.js` เข้ากับฐานข้อมูลจริง แทนอาร์เรย์ mock ที่ hardcode ไว้
6. บันทึก "ลายที่ชอบ" จาก Virtual Try-On ลงบัญชีผู้ใช้จริง (ตอนนี้เก็บไว้ใน
   state ของหน้าเว็บเท่านั้น หายเมื่อรีเฟรช)
7. ทำระบบสมาชิก/login เพื่อให้ดูประวัติการจองย้อนหลังได้ (spec ข้อ 8)
